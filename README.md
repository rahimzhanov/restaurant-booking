# 🍽️ Сайт для бронирования столиков в ресторане "Вкус"

Веб-приложение для онлайн-бронирования столиков. Клиенты просматривают доступные столики, бронируют их на удобное время, отслеживают статус брони. Администратор ресторана управляет бронью, столиками и контентом сайта через панель управления.

## 🛠️ Стек технологий

- Python 3.13
- Django 6.0
- PostgreSQL 18
- Bootstrap 5 + Bootstrap Icons
- Docker / Docker-Compose
- Gunicorn / WhiteNoise
- Git / GitHub

## ✨ Функциональность

### Для клиента
- Регистрация и вход по email
- Просмотр главной страницы с описанием ресторана и услугами
- Просмотр списка столиков с информацией о вместимости и расположении
- Бронирование столика на дату и время с проверкой пересечения
- Личный кабинет с историей бронирований
- Отмена бронирования
- Страница "О ресторане" (история, миссия, команда)
- Форма обратной связи

### Для администратора
- Панель управления со статистикой (ожидают/подтверждено/сегодня)
- Просмотр всех бронирований
- Изменение статуса брони (подтверждение/отмена/завершение)
- Редактирование параметров брони (столик, дата, время, гости)
- Управление столиками (активность, вместимость, расположение)
- Управление контентом сайта через админку (тексты на главной и странице "О ресторане")
- Просмотр сообщений из формы обратной связи

### Безопасность
- Разграничение прав (клиент/администратор) через кастомный AdminRequiredMixin
- Защита от двойного бронирования (UniqueConstraint в БД + проверка пересечения времени)
- Валидация данных на уровне модели (дата не в прошлом, гости не больше мест)
- CSRF-защита на всех формах
- Выход только через POST-запрос
- Чувствительные данные в .env (исключён из Git)

## 📋 Бизнес-ценность

Проект решает реальную проблему ресторанного бизнеса — автоматизирует процесс бронирования.

| Показатель | До автоматизации | После внедрения |
|------------|------------------|-----------------|
| Время приёма 1 брони | 3-5 минут (телефон) | ~1 минута (самостоятельно) |
| Ошибки двойного бронирования | 2-3 в неделю | 0 (система блокирует) |
| Доступность для клиентов | Только в рабочее время | 24/7 |
| Отчёт о загрузке зала | Ручной, ~30 минут | Мгновенно |

Система экономит до 10 часов рабочего времени администратора в неделю.

## 🚀 Установка и запуск

### Предварительные требования

- Python 3.13+
- PostgreSQL 18
- Git

### Локальная разработка
````
1. Клонируйте репозиторий:

    git clone https://github.com/ваш-логин/restaurant-booking.git
    cd restaurant-booking

2. Создайте виртуальное окружение и активируйте его:

    python -m venv .venv
    .venv\Scripts\activate  # Windows
    source .venv/bin/activate  # Linux/Mac

3. Установите зависимости:

    pip install -r requirements.txt

4. Создайте файл .env в корне проекта:

    SECRET_KEY=ваш-секретный-ключ
    DEBUG=True
    ALLOWED_HOSTS=localhost,127.0.0.1
    DB_NAME=restaurant_db
    DB_USER=ваш_пользователь_postgres
    DB_PASSWORD=ваш_пароль
    DB_HOST=localhost
    DB_PORT=5432

5. Создайте базу данных в PostgreSQL:

    psql -U postgres
    CREATE DATABASE restaurant_db;
    GRANT ALL PRIVILEGES ON DATABASE restaurant_db TO ваш_пользователь;
    \q

6. Примените миграции:

    python manage.py migrate

7. Создайте суперпользователя:

    python manage.py createsuperuser

8. Заполните контент сайта через админку или через Django shell:

    python manage.py shell

   Затем выполните код из файла populate_content.py (если создан) или введите данные вручную через админку в разделе "Контент сайта".

9. Запустите сервер:

    python manage.py runserver

10. Откройте http://localhost:8000
````
### Запуск через Docker
````
1. Убедитесь, что установлены Docker и Docker-Compose

2. Создайте файл .env со следующим содержимым (важно: DB_HOST=db):

    SECRET_KEY=ваш-секретный-ключ
    DEBUG=True
    ALLOWED_HOSTS=localhost,127.0.0.1
    DB_NAME=restaurant_db
    DB_USER=postgres
    DB_PASSWORD=ваш_пароль
    DB_HOST=db
    DB_PORT=5432

3. Запустите контейнеры:

    docker-compose up --build

4. Дождитесь сообщения "database system is ready to accept connections" и применения миграций.

5. В новом терминале создайте суперпользователя и заполните контент:

    docker-compose exec web python manage.py createsuperuser

6. Откройте http://localhost:8000
````

## 🔑 Основные архитектурные решения

### Кастомная модель пользователя (AbstractUser)
Наследуем стандартную модель Django, но используем email как логин. Username генерируется автоматически из email. Роль пользователя (клиент/администратор) определяет доступ к функционалу через свойство is_admin_staff.

### Class-Based Views (CBV)
Все контроллеры реализованы через CBV для чистоты и переиспользования кода:
- CreateView — регистрация, создание брони, форма обратной связи
- ListView — списки столиков и бронирований
- DetailView — детали брони
- UpdateView — редактирование, отмена, изменение статуса
- TemplateView — страницы "О ресторане", профиль
- LoginView / LogoutView — аутентификация

### Разграничение прав
Создан кастомный миксин AdminRequiredMixin, который проверяет роль пользователя перед доступом к административным страницам. LoginRequiredMixin защищает клиентские страницы.

### Валидация на уровне модели
Метод clean() в модели Booking проверяет:
- Дата бронирования не в прошлом
- Количество гостей не превышает вместимость столика
- Пересечение с другими активными бронями этого столика (по интервалу времени)

### Защита от двойного бронирования
Два уровня защиты:
1. UniqueConstraint на поля (table, date, time) — точное совпадение
2. Проверка пересечения интервалов в clean() — частичное наложение

### Управление контентом
Модель SiteContent позволяет администратору редактировать тексты на сайте (главная, "О ресторане", футер) через админ-панель без правки HTML-шаблонов.

### Безопасный выход
LogoutView принимает POST-запросы с CSRF-токеном, что защищает от CSRF-атак на разлогинивание.

### Sticky Footer
Футер прижат к низу страницы через Bootstrap-классы d-flex flex-column min-vh-100 и mt-auto.

## 🗄️ Модели данных

### User (users.User)
- email — уникальный, используется как логин
- username — генерируется автоматически из email
- role — client / admin
- phone — необязательный
- first_name, last_name, is_active, date_joined

### Table (tables.Table)
- number — уникальный номер столика
- seats — количество мест
- location — текстовое описание расположения
- is_active — активен ли столик для бронирования
- description — дополнительное описание

### Booking (bookings.Booking)
- user — внешний ключ на User (клиент)
- table — внешний ключ на Table (столик)
- date, time, duration — дата, время и длительность
- guests — количество гостей
- status — pending / confirmed / cancelled / completed
- comment — комментарий клиента
- created_at, updated_at — временные метки
- Ограничение уникальности (table, date, time)

### SiteContent (content.SiteContent)
- section — уникальный ключ раздела (home_about, home_services, about_history и др.)
- title — заголовок раздела
- content — текст раздела
- updated_at — дата последнего обновления

### ContactMessage (content.ContactMessage)
- name — имя отправителя
- email — email отправителя
- message — текст сообщения
- created_at — дата отправки
- is_read — флаг прочтения админом
